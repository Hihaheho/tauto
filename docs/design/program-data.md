# プログラムの `enum` と `struct` を証明から使う

プログラムの値（ルート、トークン、設定など）について定理を書けるように、
`inductive enum` と `inductive struct`（`enum`・`struct` の前に `inductive` を付けたもの）は、
同じ形の帰納族としてカーネルにも宣言する。その型を使う関数は、ほかの関数と同じ規則でカーネルが検査し、証明から呼べる。
`inductive` を付けない `enum` と `struct` はプログラムだけの型で、証明には現れない。
カーネルの型になるかどうかは宣言に書いたキーワードだけで決まり、欄を足したことで黙って外れることはない。

```tauto
import std::Text

inductive enum Route {
  Home
  About
}

fn segments(r: Route): List(Text) {
  match r {
    Home => Nil
    About => Cons("about", Nil)
  }
}

fn route(segs: List(Text)): Option(Route) {
  match segs {
    Nil => Some(Home)
    Cons(a, rest) => match rest {
      Nil => if a == "about" { Some(About) } else { None }
      Cons(b, more) => None
    }
  }
}

theorem about_back(): route(segments(About)) = Some(About) { Refl }
```

## 帰納族の形と、書けないもの

`crates/tauto-surface/src/inductive_data.rs` の `family` が形を決め、`crates/tauto/src/read/runtime.rs` がカーネルに渡す。

- 構成子は `enum` の構成子と同じ名前。位置の欄は `_0`、`_1`、…。`struct` の構成子は prelude の `Pair` と同じく
  `S { f: e, … }` と書き、`S { f: p, … }` で照合する。
- 欄の型は、抽出の写像の表を逆に引いたもの：`u64` は `U64`、`Bool` は `Bool`、`nat` は `Nat`（`u8`・`u32`・`i32`・`i64` も同じ）。
  その族を持つ `std` を読み込んでおく（`import std::UInt` など）。読み込んでいなければ、カーネルがそう言う。
- 決定可能な等しさ（`T::beq` など）は作らない。作られるのは構成子、フィールドと、`inductive` の標準の付属物だけである。

次のものはエラーになる（宣言の場所で、`tauto check` と Nib の型検査の両方が言う）：

- 関数を含む欄。関数のフィールドは正値性と効果の読みをカーネルに判断させることになるので扱わない。
- ホストの型（`extern { type … }`）と、行パラメータを持つ型。
- カーネルの型でない欄（`i16`、`Float`、`inductive` を付けない `enum` など）。カーネルが族を検査するときに、どの名前がないかを言う。
- 型自身の入れ子（`List(Tree(A))`）など、`inductive` として通らない形。これもカーネルが言う。

## 直積の取り出し

`A × B × C` は成分を書いた順に並べた直積で、`A × B` と `B × A` は別の型である。カーネルに渡すときだけ prelude の `Pair` を右に入れ子にした
`Pair(A, Pair(B, C))` に下ろす（次の段落以降の、カーネルに渡す直積の型）。Tauto の表面と Nib（抽出を含む）では直積と `Pair` は別の型で、
直積を `Pair` として読んだり書き出したりしない。
取り出しは型注釈 `(e: T)` で書き、`.` の後ろは常に名前である。期待される型が書かれたほかの位置（関数の引数、
型注釈つきの `let`、宣言の結果の型）でも、`e` の型がそのままでは合わず直積かラベルの部分型で合うなら、`(e: T)` と同じに
読む（`crates/tauto-kernel/src/check/implicit.rs` の `elab`）。期待される型にまだ決まっていない型の変数（ジェネリクス）が
残るときは成分を選ばない。両辺に型変数がある直積と、同じ型（ラベルを含む）の成分を二つ以上持つ辺は、型で対応づけず、エラーにする（成分を同じ順に書くか、ラベルで見分ける）。精密化（`crates/tauto-kernel/src/check/matching.rs` の `ascribe`）は次のように読む。

- `e` の型が `T` なら、`e` そのもの。
- `e` の型が直積で、`T` がその成分の一つか、成分を減らしたり並べ替えたりした直積なら（`A × B <: A`、`A × B × C <: A × C`、
  `A × B <: B × A`）、`T` の各成分を型の同じ `e` の成分から `.fst`・`.snd` で取り出し、`T` の順に `Pair` へ並べた項。
- `T` の成分の型を持つ成分が `e` に二つ以上あればエラー（ぶつかり）、一つもなければエラー。
- 同じ型の成分は、ラベル `@a T` で見分ける（`@w Nat × @h Nat`）。ラベルは型の一部で、`@w Nat` と `@h Nat` は別の型である。
  `(p: @w Nat)` はラベルの付いた成分を取り出す。
- `@a T <: T`：`T` を求められて、型が `T` の成分がなく、ラベルを外すと `T` になる成分が一つだけなら、その成分の `.value`。
  `e` の型が `@a T` で `T` を求められたときも同じ。
- `T` を `@a T` として書いた位置（`(n: @a Nat)`）では、`e` を包む。

ラベルの付いた成分の値は `@a e` と書く（`#(@name "style", @value "display:contents")`）。`e` の型が `T` なら、
値は `@a T` の成分になる。`@a` の後ろは項として読み、型なら型 `@a T`、値なら値 `@a e` で、精密化は後ろの項の型が
宇宙かどうかで読み分ける（`@a #()` は単位の値にラベルを付けたもの）。パターンも同じ形で、`#(@name n, @value v)` は各成分のラベルを外した値を `n` と `v` に当てる。

`@a T` は、精密化がラベル `a` ごとに作る一引数の帰納型 `@label.a(T)`（コンストラクタ `Mk(value: T)`）で、
そのラベルが最初に書かれた宣言の前に、書かれた `inductive` と同じ検査を受けて加わる。名前に `@` を含むので
利用者は書けず、`=>` の一覧にも挙げない。値 `@a e` は `@label.a.Mk(e)`、パターン `@a p` は `@label.a.Mk(p)` である。
Nib ではラベルは型の印で、値 `@a e` は `e` そのもの、パターン `@a p` は値の型に `@a` があることを確かめて `p` を当てる。
一つの値に付いたラベルは集合で、`@a @b T` と `@b @a T` は同じ型である。精密化はラベルを名前の順に並べ
（外側から `@a`、`@b`）、値とパターンの `@b @a …` も同じ順に読む。Nib のパターン `@a p` は `@a` だけを外し、
残りのラベル（`@b T`）を `p` に当てる。

直積は成分の列で、単位 `Unit` は成分のない直積である。精密化は直積の型を書き出すときに、
`Unit` の成分を除き（`A × Unit` は `A`）、成分が一つ残れば
その成分そのもの、一つも残らなければ `Unit` にする。値とパターンも同じで、`#()` は落とす
（`#(a, #())` は `a`）。入れ子の直積は平らにしない：`(A × B) × C` は `Prod(Prod(A, B), C)` で、`A × B × C`
（`Prod(A, Prod(B, C))`）とは別の型。`#(#(a, b), c)` も `#(a, b)` を一つ目の成分に持つ。書き方で平らにすると、
`T × C` に `T := A × B` を代入したときと意味が食い違うため。カーネルは書き出された正規形だけを見る
（`crates/tauto-surface/src/surface/qualify.rs` の `product_type_members`・`flatten_pair_value`・`flatten_pair_pattern`）。

カーネルに渡す直積の型は、成分を書いた順に並べた `Pair` の入れ子である。値 `#(…)` とパターン `#(x, y)` は、
型の成分に位置で当たる。ラベルの付いた成分も位置で当たり、`@a x` は成分の型のラベルが `a` であることを確かめる。
同じ型の成分を含む直積も位置で当たるので、パターンにあいまいさはない。Nib の直積も同じく書いた順に並び、
位置で当たる。

カーネルが受け取るのは書き出された射影の項で、カーネルに部分型の規則は足さない。部分型が効くのは期待される型が
書かれた位置だけで、`=` の両辺のように型を合成する位置では効かない。

## 健全性

- カーネルに規則は足さない。帰納族は `inductive` と同じ検査（正値性、宇宙、eliminator と iota 規則）を受ける。
  `inductive` を付けた型が族として通らなければ、その宣言とそれを使う証明がエラーになる。
- 所有権（affine など）は実行の側の規律で、カーネルの項には現れない。証明は値を消去されるものとして扱うので、
  帰納族として複製できても実行の所有権は変わらない。
- `! {Div}` を行う関数は、停止が示されないのでカーネルに入れない。往復などの定理にしたい関数は、
  `Div` を行わず構造的な再帰で書く。
- 実行には元の `enum` と `struct` がそのまま使われ、eval・JavaScript・Rust の各バックエンドが作るものは変わらない。
