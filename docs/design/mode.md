# 規則からの関数生成と判定の証明

`mode!` は帰納的な関係の各位置に役割を与え、規則から判定関数と答えの型を作る属性マクロである。
目的は、関係の規則、計算、正しさの証明を一緒に保ち、人間が入出力と保証を確認できるようにすること。
生成器は `std/Mode.taut` にあり、帰納型、関数、等式、通常の構造再帰だけを使う。

## 実装と保証

入力全体を `i`、出力の型を `O(i)`、元の関係を `R(i, o)` とする。
これは契約の数学的な記法であり、別の構文ではない。

| 結果 | フィールドの順序 | 保証 |
|---|---|---|
| 出力がある成功 | 出力 `o`、導出 `h`、一意性 `unique` | `R(i, o)` と、任意の `o'` とその導出に対する `o' = o` |
| 出力がある拒否 | 反証 `refute` | 任意の `o` と `R(i, o)` の導出から `False` を得る |
| 出力がない成功 | 導出 `h` | その入力での関係が成立する |
| 出力がない拒否 | 反証 `refute` | その入力での関係の導出から `False` を得る |

成功と拒否の構成子名は属性の指定に従う。保証を弱めるオプションはない。
一意性は出力値についての証明であり、導出の証明同士を比較するものではない。
複数の異なる出力を持つ関係に、この契約を満たす全域関数は作れない。

判定関数と結果の帰納型の二つを生成する。宣言の種別と名前を属性の生成物一覧に書き、
一覧との過不足は通常のマクロの検査で拒否する。元の関係は保持する。
名前を指定していない補助定理を公開宣言として生成しない。
独立した健全性、完全性、一意性の定理が必要なら、結果を場合分けする通常の定理として書ける。

## 役割と規則の受理条件

構文の入口は [`macro.md`](macro.md)「`mode!`（`std/Mode.taut`）：規則を関数にする属性マクロ」にある。
すべての位置に宣言順で役割を与え、位置名は重複させない。
`rec` は一つで、生成する関数の先頭の引数になる。`in` はその後に宣言順で並び、
`out` はゼロか一つ。複数の値は一つの出力のデータにまとめられる。

関係は検査済みの帰納的な `Prop` である。関係の引数は、帰納型の一様なパラメータではなく、
役割を与えるシグネチャの位置に書く。シグネチャの名前付き束縛は位置名に読み替える。
型の依存は、再配置した引数の順序でも前の入力だけを参照できなければならない。
出力型も入力だけで決まる。依存する型や添字のために必要な精密化を生成できない場合は、
生成した宣言を通常の検査が拒否する。依存を消した近似の契約は使わない。

| 対象 | 条件 |
|---|---|
| 入力パターン | 変数と有限の入れ子の構成子。構成子のフィールドをすべて書き、入力全体で変数を重複させない |
| 規則の選択 | 入力全体の構成子パターンによって適用規則が高々一つに定まる |
| 前提の順序 | 宣言の順に処理し、前提の入力はそれまでに束縛された値から作る |
| 前提の出力 | 未束縛の名前への束縛、構成子の分解、既知の変数との等値比較で検査できる |
| 結論とデータ | 結論の出力と構成子の引数は、入力か先行する前提から得られる |
| 再帰 | 再帰位置が結論の入力パターンの厳密な部分項であり、通常の構造再帰の検査も通る |
| 別の関係 | 明示した `via` の関数が同じ判定の契約を満たす |
| 比較 | 比較する変数の宣言型に対応する `eq` が一意に指定されている |

暗黙引数は通常の第一階のマッチングの範囲で精密化される。
規則の構成子自身のジェネリクスも、入力か前提から値が決まることを確認する。
前提の入力が未束縛なら、その前提を後へ移動して試し直すことはしない。

前提を実行すれば互いに排他的だと分かる規則でも、入力パターンが重なるものは受理しない。
一つの位置に変数と構成子が混在していても、他の位置で分離できれば受理する。
規則の順序を変えて優先順位を付けたり、失敗した規則の次を試したりしない。
この制限は生成器の受理条件であり、Tauto で定義できる関係の制限ではない。

## 前提と比較の接続

自身の関係の前提は再帰呼び出しになる。別の関係の前提は `via` に明示した関数に渡す。
`via` の関係は最後の位置が出力で、それ以外は宣言順の入力である。
別の引数順を持つ関数は、並べ替える通常の関数で接続する。
出力のない別関係への直接の接続や、呼び出しごとの方向の選択は行わない。

接続先の成功は出力、導出、一意性の三つ、拒否は全出力の反証を持つ。
構成子のフィールド数が足りなければ契約不足として生成を拒否する。
フィールド数が合っていても、その型が契約に合わなければ生成した関数の検査が拒否する。
名前の登録を証明の代わりにはしない。

`eq` の成功は実際の等式の証明を一つ、拒否はその等式から `False` を得る証明を一つ持つ。
比較型ごとに一つの関数を指定する。指定の重複、比較に必要な指定の欠落はエラーになる。
対応は比較する変数の宣言型との構造的な照合で決め、型の別名を展開して判定器を探したり、
補題や instance を検索したりしない。
入れ子の出力の一部を比較するときは、その部分の型の判定器を使う。

構造再帰で表せない接続先も、通常の検査を通る全域関数なら利用できる。
整礎再帰には `std/WellFounded.taut` の契約と `decreasing_by` を使う。
未完成の宣言や発散の effect を持つ関数から、カーネルが検査する判定関数は作れない。

## パターン分割と証明の生成

入力パターンを列、規則を行とする表から場合分けを作る。
構成子を要求する列を選び、その型のすべての構成子に対する腕を明示する。
構成子のフィールドは後続の照合対象となり、入れ子のパターンも同じ処理で分割する。
変数の位置は、その腕で再構成した値に置き換える。
候補が複数残る葉は重なりとして拒否する。候補がない葉では、元の関係の導出を反転して反証する。

葉では前提を順に一度ずつ呼び、導出と一意性を保持する。
任意の別の結論の導出については、選ばれた規則を反転し、先行する前提の一意性で出力をそろえる。
後続の前提がその出力に依存する場合は、後続の引数と証明を一般化して等式を除去する。
後続の判定が返した一意性と反証も同じ一般化に含め、入れ子の証明のゴールまで精密化を反映する。
必要な前提や反証は型を明示した引数として運び、反転による入力の精密化を反映させる。

| 分岐 | 証明の構成 |
|---|---|
| 前提が拒否された | 任意の結論の導出から前提を取り出し、入力をそろえてその反証へ渡す |
| 出力の構成子が異なる | 一意性による等式を、異なる構成子の等式として反転する |
| 出力の変数が異なる | 一意性から得た等式を比較する部分へ写し、等値判定の反証へ渡す |
| 前提がすべて成功した | 規則の構成子で導出を作り、別の導出の前提をそろえて出力の一意性を示す |

入れ子の部分の比較では、その部分を取り出す通常の関数を生成し、等式の合同性を用いる。
この関数は比較する部分の型を返し、すべての構成子の腕を持つ。
出力の分解も、入力の照合と同じく構成子ごとの腕を明示する。
探索をもう一度実行して正しさを確かめる処理は生成しない。

## 信頼の境界と診断

生成器は信用しないマクロである。生成した結果型と関数を、名前つきの検査器による精密化を経て
`crates/tauto-kernel/src/check/core.rs` の検査へ渡す。型付け、簡約、変換の規則は増やさない。
証明のフィールドは `Prop` であり、実行時の消去は通常の規則に従う。
型を入力に取る契約もカーネルで検査できるが、抽出後の実行にはバックエンドの制限がある。
結果型の型パラメータが証明のフィールドにだけ現れる場合、消去後は未使用になり、
Rust バックエンドではその結果型をコンパイルできない。型入力の契約は独立した検査ケースで扱う。

結果型自身も生成するので、core の受理だけでは指定どおりの契約を生成したことまでは保証しない。
ケースでは元の関係を参照する独立した期待型を使い、成功、反証、一意性を取り出して検査する。
結果型と関数を一緒に弱める誤りを、成功例の型検査だけで見逃さないようにする。
公理への依存は通常の依存追跡で扱う。

構成子の一覧とフィールド数は、マクロが `elab_siblings` と `elab_constructor_arity` で読む。
これらは既存の宣言を読むだけである。フィールド数は帰納型の一様なパラメータを除き、
構成子自身のジェネリクスを含む。構成子でない名前には値を返さない。

役割の過不足、名前の重複、入力の重なり、未束縛の前提や出力、減少しない再帰、
接続のフィールド不足、比較指定の不足は生成時に診断する。
規則や前提についての診断は、その名前と位置を持つ。
より複雑な添字の精密化や接続の型の不一致は、生成した宣言の通常の型エラーとして示す。
展開した項と生成元は、既存の `macro expand`、`trace`、`inspect` で確認できる。

生成器の資源上限や検査の中断は診断であり、実行する関数の反証ではない。
暗黙の fuel、未確定の論理変数、規則の探索、全解の列挙は `mode!` の責務に含めない。

## 検証

`cases/check/mode.eure` は役割指定、生成物の一覧、基本的な規則の選択を検査する。
`cases/check/mode-certificates.eure` とその fixture は、手書きの契約、生成した契約、
入れ子の照合、異なる型の部分の比較、成功と拒否の計算結果、接続の契約不足、
不正な反証の拒否を検査する。計算で確認する性質は `Refl` の定理としても残す。
`cases/check/mode-composition.eure` は複数の前提間の出力の受け渡しと、同じ出力を要求する前提を検査する。

`examples/lambda/Lib.taut` の型推論は複数の前提と等値判定を接続する。
`meta/Kernel.taut` の環境検索と自然数の大小判定も同じ契約を持つ。
`examples/stack-check/` は命令とプログラムの型付け規則を接続し、分岐後のスタック型を照合する。
実行器が型違いやスタック不足で停止しないことは、生成した導出を使う別の定理で示す。
標準ライブラリと `meta/` は、通常の検査、lint、整形、公理への依存の検査を通す。

## 未決定

単一化と候補の列挙は、明示したデータと契約を持つライブラリとして扱う設計対象である。
`mode!` に探索の状態や実行方向の推測を組み込むことはしない。

### 単一化

対象は、利用者がデータとして定義する変数、第一階の項、置換、制約とする。
証明の穴やカーネルの束縛変数を未確定変数の格納場所にしない。
成功には入力置換の保存と全制約の充足、拒否には許された範囲に解がない証明を持たせる。
最汎性が必要なら、任意の解が返した置換を通じて因数分解できる証明も契約に含める。
型推論の健全性、完全性、主型性は対象の規則について別々に示す。

`totes/nibcheck/src/checker.taut` と `unify_sound.taut` を再利用の検討対象とする。
型や状態の不変量を異なる利用箇所で共有できると確認するまでは tote に置く。
高階単一化、変換を法とした汎用単一化、暗黙引数の推論範囲の拡大は対象に含めない。

### 候補の列挙と上限のある探索

有限の列挙結果には、各候補の導出と、関係を満たす全出力が列挙に含まれる証明を持たせる。
出力の重複は許し、重複除去のためだけに等値判定を要求しない。
途中の結果は、候補の健全性と未処理の状態を保持し、網羅性を持つ完了結果と区別する。
完全な空の列挙からは不在の証明を得られるが、途中までの空の列挙からは得られない。

上限のある処理は、成功、反証つきの拒否、未判定を区別する結果型を用いる。
一段の分岐が有限でも探索全体の停止は保証されない。
有限の対象、整礎な減少、明示した上限のどれを使うかを入力と契約に表す。
深さを制限した関係の網羅性を、元の関係全体の網羅性として扱わない。

規則からの列挙器生成は、これらの契約と利用箇所を定めてから検討する。
利用者のマクロで探索する場合も規則集合と上限を明示し、得た証明項を通常の検査へ渡す。
候補提示の道具については [`lemma-search.md`](lemma-search.md)「Lemma discovery」による。
