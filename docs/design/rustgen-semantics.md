# Rust 生成先の構文と意味論

`totes/rustgen/model/` は、`crates/tauto-rustgen` をセルフホストする際の
Nib → Rust の意味保存証明に使う生成先言語である。入力を読む既存の
`totes/rustgen/src/` の Surface バックエンドとは独立している。

## 構文と静的な情報

`syntax.taut` の `inductive_syntax!(rs, …)` が Rust の具象構文、パーサー、
帰納的な木 `rs::Program::I`、`rs::Expr::I`、`rs::Pattern::I`、`rs::Ty::I` を定義する。
`.I` の葉は綴りであり、位置と構文マクロの識別子の文脈は実行の意味に含めない。
生成表は `model/.tauto-syntax/` に置く。

意味を持つ生成形は `source.taut` の `RsRepresents` によって制限する。
文法が読めることだけでは、その木に評価規則があることにはならない。
`RsRepresents(sig, scope, control, expr, ty, syntax)` は、具象構文の木 `syntax` が、
解決された式 `expr` を型 `ty` の式として表すことをいう。複合式を任意の関数で
解釈する口はない。束縛、分岐、適用、パターン、キャプチャはそれぞれの構成子で対応する。

`sig` は名前解決と型検査を終えた宣言環境で、型の綴り、Copy/move の区別、
参照先、フィールドの宣言順、呼出しの引数と結果、コンストラクタ、外部関数の ABI を持つ。
ポインタ幅は環境に明記する。`scope` は局所名と型の列で、解決後の局所変数はその列の添字である。
`control` は関数の結果型と囲んでいるループのラベル・結果型を持つ。
クロージャと非同期本体に入るとループの列を空にする。

静的環境は Rust の型推論器や借用検査器の代わりではない。対象は、その環境が宣言を
正しく表し、Rust の型検査・借用検査を通る生成物である。特に Copy の宣言、
フィールド配置、参照の寿命、呼出し可能な種類、型引数と trait の解決、
データ宣言・型別名と環境の対応は、利用側が満たす前提である。
`RsSourceProgram` はすべての実行する関数本体を同じ関数表に結ぶが、
データ宣言のレイアウトや借用規則を再検査する関係ではない。

## 生成形

生成形は Rust として有効な一つの明示的な書き方に揃える。
条件、演算子、参照、逆参照には括弧を付け、ブロックは末尾式を持つ。
関数・型・コンストラクタの道筋と型引数は静的環境で解決されている。
局所名は `v` に自然数を続け、ラベルは `'l` に自然数を続ける。
束縛名は同じスコープの外側の名と再利用せず、大域名を隠さない。

| backend が使う機能 | モデルでの形 |
| --- | --- |
| リテラル、局所変数、フィールド、参照・再借用 | `RsLit`、`RsRead`、`RsField`、`RsDeref`、`RsRef` |
| 宣言順のフィールドを持つ struct・enum・直積 | 型表とコンストラクタ表、`RsAggregate` |
| `let`、文の列、代入 | `RsLet`、`RsSeq`、`RsWrite` |
| `if`、短絡する論理演算 | `RsIf`。`&&`・`||`・`!` にも具象構文との対応規則を持つ |
| place / 値に対する `match`、ガード、入れ子パターン | `RsMatchPlace` / `RsMatch`、`RsCase`、`RsPattern` |
| 関数、間接呼出し、再帰 | `RsFunction`、`RsCall`、プログラムの関数表 |
| `Fn`・`FnMut`・`FnOnce` とキャプチャ | `RsLambda`、明示的なキャプチャの初期化、所有する `move` クロージャ |
| 借用するクロージャ | キャプチャに参照を渡し、呼出し時には `RsRef` で借用する |
| `loop`、`break`、`continue`、`return` | ラベルを持つ制御結果 |
| `async move`、`.await` | `RsFuture` と `RsAwait` |
| 実行時ライブラリ、外部 API、scalar の演算 | 型付きの直接呼出し `RsPrimitive` と外部契約 |

関数の引数、コンストラクタのフィールド、外部呼出しの引数は、左から右に型注釈つきの
私有の局所変数へ束縛してから渡す。これにより Rust の整数の既定型や曖昧な generic の
推論に依存しない。間接呼出しでは、その前に呼出し先も束縛する。

キャプチャは外側で評価してから `move` する。本体の先頭で各キャプチャ全体を一度
共有借用し、使うフィールドだけにキャプチャが分割されない形にする。
`Fn` は `Rc::new`、`FnMut`・`FnOnce` は `Box::new`、future は `Box::pin` を使う。
クロージャの引数と結果の型は周囲の型注釈から Rust が検査する。
高階の寿命量化を含む型・境界も文法で表せる。状態を借用する callback の状態は
明示的な引数として渡せる。

この生成形は backend の出力文字列の全字面を受理するパーサーではない。
`while` はラベルつきのループ、メソッド呼出しは解決済みの直接呼出し、
scalar 演算は対応する実行時 API または完全修飾した演算の呼出しで表せる。
浮動小数点リテラルは `from_bits` を使い、NaN と符号つきゼロを含むビット列を保持する。
既存出力の字面をこの生成形へ変える変換自体は意味保存証明に含める必要がある。

`use`、モジュールの包み、公開 API の facade、定数の配置、診断用マクロ、
埋め込む構文パーサーの Rust 実装、マニフェストで指定する任意の Rust binding は
この式言語の実装対象ではない。実行する部分は名前と ABI を持つ外部契約で接続する。
型、関数、実行時境界のいずれにも対応がない構文を、暗黙に外部呼出しとは解釈しない。

## 評価

`core.taut` が解決後の構文・値・記憶域・制御結果を定義する。
`semantics.taut` の相互帰納的な関係が有限の評価導出である。

| 判断 | 意味 |
| --- | --- |
| `RsEval(program, rt, env, expr, heap, out, next, trace)` | 式を評価する |
| `RsEvals` | 式の列を左から右に評価する |
| `RsApply` | 大域関数、所有する callable、借用した callable を呼ぶ |
| `RsSelect` | パターンとガードを順に試す |
| `RsFinish` / `RsDrop` | スコープと値を解放する |
| `RsSourceEval` | 具象構文との対応を持つ式を評価する |
| `RsProgramRuns` | 具象プログラムの関数表を結び、入口を呼ぶ |

`env` は局所変数のアドレスの列である。アドレスは根の割当て番号とフィールドの道筋を持つ。
記憶域の番号は解放後も詰めず、解放したセルへの代入で復活させない。
move は元の場所を未初期化にする。部分 move 後は残りのフィールドを使えるが、
未初期化のフィールドを含む値全体は読めない。共有参照は Copy、可変参照は move する。
借用による別名の合法性は、前述の Rust の借用検査の前提に含める。

place を選択対象とする `match` はその場所を使い、値を対象とする `match` は一時領域を持つ。
ガード中の値束縛は選択対象の元のフィールドの場所を借りる。参照束縛は参照の一時セルを持つ。
ガードが真のときだけパターンの Copy/move を確定し、本体の所有する束縛を作る。
偽なら借用の一時セルを外して次の腕へ進む。ガードの外部への作用は取り消さない。
ワイルドカードは値を読まず、既に move したフィールドも飛ばせる。
一致する腕がない場合の評価規則はない。網羅性または明示的な失敗の腕が必要である。

通常の引数評価は左から右、代入は右辺が先である。
代入は元の値の解放後に書き込む。右辺や引数列の途中で異常が起きた場合も、
既に所有した一時値を解放する。局所変数・引数は束縛と逆順、データのフィールドは宣言順に解放する。
クロージャと future のキャプチャの解放順は置換関係で表し、一つの順に固定しない。
`FnOnce` は呼出し時に環境を消費する。共有借用で呼べるのは `Fn`、可変借用では `Fn` と `FnMut` である。

結果は正常値、関数の `return`、ラベルつき `break`・`continue`、panic、終了コードを持つ
プロセス終了、abort を区別する。通常のスコープ離脱と panic は解放を行い、
終了と abort は解放を行わない。panic の巻き戻し中に解放が panic すると abort する。

## 実行時境界と証明の範囲

`RsRuntime` は外部操作名・値引数・記憶域から、結果・記憶域・イベント列への関係を渡す。
これは公理の宣言ではなく、意味論と後の定理の明示的な引数である。
`RsRuntimeOutcome` は外部操作から呼出し元への `return`・`break`・`continue` を許さない。
外部操作の終了・失敗・資源の解放は、この関係の契約として明記する。
`RsDrop` は既に巻き戻し中かを引数に取り、入れ子のフィールドとキャプチャの解放にも渡す。
`drop_handle` の値引数は、その Bool と handle であり、参照カウントと最後の所有者による解放も含める。
callback を呼ぶ契約は `RsApply` を使って同じプログラム・記憶域・実行時関係に戻る必要がある。
任意のホストコードがこの契約を満たすとは仮定しない。

`integer.taut` は固定幅の範囲、checked な加減乗算・符号反転・比較と、
実行時の非負の任意精度整数の加減乗算・比較を計算として定義する。
自然数の減算の負の結果も失敗であり、ゼロへの飽和ではない。
これらは実行時 API の契約を具体化する部品で、Rust の任意の整数演算子の overflow 方針を
表すものではない。浮動小数点演算、テキスト、コンテナ、共有可変セル、
効果の dispatch、継続、予算の通知、外部 I/O は、それぞれ対応する実行時契約で接続する。
Rust の物理的な割当て失敗とネイティブスタックの上限は、この記憶域の意味論に含めない。

`RsFuture` はキャプチャを持つ未実行の計算で、`RsAwait` が一度だけ実行する。
これは単一の計算の有限の完了を観測する意味論であり、poll の回数、waker、
並行実行の交錯、公平性、待機中の取消しの意味論ではない。
有限の結果がないことから、発散や永久待機と不正な実行とを区別する定理は得られない。

後の意味保存定理は、Nib の値・記憶域・外部イベントとこのモデルとの対応を指定し、
`RsRepresents` と `RsSourceProgram` の導出を生成し、利用する実行時操作の契約を満たすことを示す。
その上で有限の評価について結果、制御結果、イベント、残る所有権の対応を述べられる。
発散・並行スケジュール・取消しまで保存する主張には、それらを観測する意味論も必要である。
Rust コンパイラと機械コードの正しさ、Rust の型検査器・借用検査器の正しさは対象に含めない。
