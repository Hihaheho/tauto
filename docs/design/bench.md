# ベンチマーク

`tauto bench` は指定したソースファイルかパッケージを Rust backend の release
設定で一度ビルドし、同じ実行ファイルを繰り返し起動する。`--backend rust` は省略できる。
ビルド、生成、型検査の時間は測定に含めない。ビルドの依存解決と出力先は
`tauto build --backend rust --release` と同じで、`TAUTO_TARGET_DIR` も適用する。

`--warmup` は測定前の実行回数（既定 1、0 から 100）、`--samples` は
測定する実行回数（既定 10、1 から 1000）を指定する。
**各回にプログラムの副作用が繰り返される。** 実行を取り消したり、ファイルや
外部状態を元に戻したりはしない。標準入力は空で、対話入力は渡さない。
`--timeout-ms` は各回の起動から出力収集までの上限（既定 30000、1 から 3600000）を
指定する。超過時には直接起動したプロセスを停止し、統計を出さずに失敗する。
extern が作った子孫プロセスや外部サービスを停止する保証はない。

測定は経過時間であり、CPU 時間ではない。プロセスの起動、終了と標準出力・
標準エラーの収集を含む。各回は別プロセスなので、前の回のメモリ状態を引き継がない。
短い処理では起動コストが支配的になる。これは関数ごとのプロファイラでも、
コンパイラのフェーズ別測定でもない。終了確認は 1 ミリ秒間隔の polling であり、
出力収集のスレッドと終了確認の待ち時間も測定に含まれる。

全実行が正常終了し、標準出力・標準エラーが最初の実行とバイト単位で一致することを
確認する。異常終了または不一致ではコマンドが失敗し、統計を出力しない。
比較には warmup も含む。各回の出力はストリームごとに 1 MiB までメモリに保持し、
超過は失敗として扱う。プログラムの出力内容そのものは表示しない。

統計はミリ秒単位の最小値、中央値、平均、最大値、母標準偏差。
`--json` は測定値の配列、統計、測定方式、warmup 回数、出力のバイト数と整合性を
一つの JSON object に出力する。ビルドと実行回数の案内は標準エラーに出す。
引数が不正なら終了コード 2、ビルド・実行・整合性検査の失敗なら 1、成功なら 0。
