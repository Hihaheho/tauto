# tote のコマンド（`tauto NAME`）

tote は `Tauto.eure` に名前の付いたプログラムの入口を書いて、`tauto` のコマンドを足せる。プロジェクトが直接依存する tote と、プロジェクト自身のコマンドは、`tauto NAME ARGS…` で走る。中身は `tauto run` と同じく検査して評価器で走らせるプログラムで、ホストへの権限は既定ですべて拒否する。権限を与えるのはプロジェクトの `Tauto.eure` の `trust.commands` だけである。

## 宣言

```eure
package {
  name = "bikkuri"
  version = "0.1.0"
}

commands {
  bk {
    main = "cmd/bk.taut"
    about = "bikkuri のアプリの雛形を書き、開発サーバーで動かす"
  }
}
```

- 名前は tote の名前と同じ規則（小文字・数字・`-`、英字で始まる）。
- `main` は tote の中の `.taut` か `.tauto` のファイルで、tote の根から `.` も `..` も使わずに書く。そのファイルはこの tote に属し（間にほかの `Tauto.eure` がない）、ソース（`src` と `package.additional-sources`）の外になければならない。ソースの中にあると、この tote に依存するすべての tote がそれを読んでしまう。依存として読むとき、コマンドの `main` はほかのどの読み込みにも入らない。
- `about` はそのコマンドがすることの一行で、`tauto --help` と `tauto audit` がそのまま出す。
- 要る権限は書かない。どの種類が要るかは型（effect の行）から求める（「権限」）。

`main` は `src/main.taut` と同じく最上位の文を持つプログラムで、tote のソースとその依存を見て名前を解決する。`tauto NAME` の後ろの引数は、すべて `argv()` になる。

## どのコマンドが走るか

`tauto NAME` は次の順に探す。

1. `tauto` 自身のコマンド（`run`、`test`、`check` など）。tote が同じ名前のコマンドを書いても走らない。`tauto --help` はそれを「組み込みのコマンドと同名で走らない」と示す。
2. プロジェクトの `trust.commands.NAME` が `tote` で名指した tote のコマンド。名指した tote がそのコマンドを持たなければ誤り。
3. プロジェクト自身のコマンド。
4. プロジェクトが直接依存する tote のコマンド。二つ以上の tote が同じ名前を持てば、どれも選ばずに誤りにし、`trust.commands` で選ぶよう求める。

推移的な依存のコマンドは現れない。コマンドを足せるのは、プロジェクトが `Tauto.eure` に名指した tote だけである。

プロジェクトは、走らせたディレクトリから上にたどって最初に見つかる `Tauto.eure` である。プログラムの作業ディレクトリは走らせた場所のままで、利用者が引数に書いた相対パスはそこから読む。`tauto` の前に置いた `--offline` と `--fresh` は `tauto` が読み、コマンドの名前より後ろのものはコマンドの引数である。

## 権限

コマンドは依存の作者が書いたコードなので、その権限はプロジェクトが信頼として決める。

```eure
trust {
  extern = ["regex"]
  commands {
    bk {
      tote = "bikkuri"
      read = ["src", "public"]
      write = ["dist"]
      net = ["127.0.0.1:3000"]
    }
  }
}
```

- キー（`bk`）はコマンドの名前、`tote` はそのコマンドを持つ tote で、必須。許可は「tote と名前の組」に結びつく。別の tote が同じ名前のコマンドを持っても、この許可は渡らない。
- ほかのキーは権限ファイル（[`host-effects.md`](host-effects.md)「権限」）と同じ形と意味を持つ：`read`、`write`、`env`、`net`、`run`、`clipboard` で、値は `true` か名前のリスト。`all` は受け付けない。他人のコードには、要る種類を一つずつ名指して与える。
- `read` と `write` の相対パスは `Tauto.eure` のあるフォルダから読む。どのサブディレクトリから走らせても意味が変わらない。
- `trust` を読むのはプロジェクトの `Tauto.eure` だけで、依存の `trust` は何も許さない。
- `tauto NAME` は `--allow-*` も `--permissions` も読まない。それらはコマンドの引数として渡る。許可を広げるには `Tauto.eure` を変えるしかなく、その変更はコミットされてレビューに乗る。
- プロジェクト自身のコマンドも同じで、`tote` に自分の名前を書いて与える。

コマンドを検査したあと、最上位に届く標準エフェクトとタスクが行う標準エフェクトから要る種類を求め（`tauto run` の「実行前の拒否」と同じ）、許可に無い種類があれば実行を始めずに失敗する。そのとき、足すべき `trust.commands` の節を示す。範囲（どのパス、どのホスト）は型から決まらないので、プロジェクトが書く。範囲の外への要求は実行中に `Err(Denied(..))` になり、対話的に尋ねることはしない。

`extern` はこれまでの規則がそのまま効く。コマンドを読むときも信頼の根はプロジェクトで、コマンドを持つ tote は依存として読む。だから依存の tote が `extern` を宣言していれば、プロジェクトの `trust.extern` が名指さない限り読み込みで拒否する（[`host-effects.md`](host-effects.md)「依存の extern」）。`main` はその tote に属するので、tote の extern を包む関数を呼べる。

コマンドのコードは `Tauto.lock` が固定する。変わるのは `tauto add`、`update`、`lock` が新しいコミットを採ったときだけで、そのとき信頼する索引と公開後の待ち時間が効く（[`totebag.md`](totebag.md)「Trusted indexes」）。

## 実行

`tauto NAME ARGS…` は、入口をコマンドの `main` にした `tauto run` である。

1. プロジェクトを見つけ、名前からコマンドを選ぶ（「どのコマンドが走るか」）。
2. コマンドの tote を読む。Git の依存は `tauto run` と同じくプロジェクトの `Tauto.lock` から取り、lock は変えない。`--offline` も効く。読むのは tote のソースとその依存、最後に `main` で、プロジェクト自身のソースはプロジェクト自身のコマンドのときだけ読む。
3. `tauto run` と同じ検査をする。証明（穴は拒否）、型、行、所有権。検査を通らないコマンドは走らない。
4. 要る権限の種類を許可と照らす（「権限」）。
5. 評価器で走らせる。`tauto dev` と同じく、出力は起きた時点で書き、step 数に上限を置かない（利用者が起動し、Ctrl-C で止める道具だから）。終了コードは `exit` の値。

`tauto check --tote DIR` は、tote の各コマンドの `main` も `tauto NAME` が読むとおりに読んで検査する。`main` が ソースの中にあるなど、宣言が守られていなければ誤りにする。

## 見つけ方

コマンドは、実行せずに読める場所に出る。どれもマニフェストとソースを読むだけで、ネットワークには出ない。

| 場所 | 出すもの |
|---|---|
| `tauto --help`（プロジェクトの中） | 組み込みのコマンドの後ろに、プロジェクトのコマンドを一行に一つ：名前、tote、`about`、状態（与えた権限の種類、名前が衝突して走らない、組み込みと同名で走らない）。取っていない Git の依存は読めなかったと示す |
| `tauto audit [--json]` | tote ごとの `commands`：名前、`main`、`about`、プロジェクトが与えた権限の種類。`main` の宣言する effect と extern も tote の一覧に入る |
| `tauto add` | 足した tote のコマンドと、それが `trust.commands` で許可されるまで権限なしで走ること |
| 拒否の知らせ | 足りない種類と、`trust.commands` に足す節。名前の衝突では、両方の tote と選び方 |

`tauto NAME --help` はコマンド自身に届く。

## 未決定

- Rust バックエンドで走らせること。評価器は遅いので、重いコマンドは `tauto build` した実行ファイルで走らせたい。生成した実行ファイルは先頭の `--allow-*` を権限として読むので、許可はその形で渡せる。置き場所と、何で引き当てるか（`source` と `tauto` の版）、依存の Rust crate の扱いを決める。
- `tauto update` が、コマンドの要る権限の種類が増えたことを示すこと。要る種類は検査した行から求めるので、更新の前後で両方を検査する必要がある。
- 名前の付け替え（二つの tote が同じ名前を持ち、両方を使いたいとき）。今はプロジェクト自身のコマンドで片方を包めばできる。
- プロジェクトの外で使う道具（どこでも `tauto rg` を使いたいとき）の lock と許可の置き場所。
- 変更のたびにコマンドを起動し直すこと（`tauto dev` との組み合わせ）。
