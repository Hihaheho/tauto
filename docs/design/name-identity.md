# 名前の同一性

宣言と局所束縛の同一性を表す型は `tauto-identity` にあり、表層と実行時で共用する。
表層では `tauto_surface::identity`、実行時では `tauto_rt::identity` から同じ型を使う。
この型は、表層の他の部分に依存しない。module の道筋、import、公開範囲を知らず、
「どの綴りがどの宣言を指すか」は決めない。決めるのは `visibility.md` の規則と
修飾の処理で、この文書はそこで決まった名前の宣言に付く ID を述べる。

## 原則

- 表示名は同一性に使わない。等しさ、順序、ハッシュは ID だけで決まり、同じ表示名を
  持つ別の宣言は別の宣言である。
- 宣言の ID と局所束縛の ID は別の型で、互いに代わりにならない。
- 参照を予約することは、その宣言が受理されたことを意味しない。受理するのは
  カーネルだけである。

## `Name`

`Name` は、解決の前の名前と解決した参照を区別する。

| 種類 | 意味 |
|---|---|
| `Spelled` | 書かれた綴り。まだ解決していない |
| `Global` | 宣言への参照 `DeclRef` |
| `Local` | 局所束縛への参照 `LocalRef` |
| `Selection` | 型で選ぶ前の、宣言の候補の有限集合 |
| `Effect` | 宣言を束縛した effect と、その引数と行パラメータ |

種類が違う名前は、表示名が同じでも等しくならない。`Name` は表示名を文字列として
読めるが（`Deref<Target = str>`、`Display`）、表示は同一性ではない。

effect の行・`perform`・handler の操作名は、effect の宣言表で束縛する。
同じ綴りの関数が見えていても、その関数の ID に置き換えない。
関数と effect が同じ綴りで宣言される場合も、それぞれの宣言 ID を保持する。

## 宣言の参照

`DeclRef` は宣言ごとに一つで、複製は同じ参照である。表示名は修飾した完全名
（`app::List`、`std::prelude::List`、`M::T::C`）を持つ。

- **生成される宣言**は、所有する宣言の ID と生成の種別 `Generation` で識別する
  （eliminator `rec`・`ind`、等価性の補助、入れ子の補助 `Nested(n)`、effect の
  操作・引数・応答・腕、整礎再帰の補助関数と等式、opaque 関数の本体と等式、
  共通の燃料引数を持つ相互再帰の要求型・応答型・読み取り関数・ゼロ腕・結果の射影）。
  同じ所有者と種別は同じ参照で、別の所有者の同じ種別は別の参照になる。
- **構成子**は、所有する型と型の中の位置 `Constructor(i)` で識別する。綴りは識別に使わないので、
  別の型の同じ綴りの構成子は別の参照になる。
- **クラスのメンバー**は、クラスの ID、メソッドか法則かの種別、宣言内の位置で識別する。
  インスタンスのメンバーは、メンバーの ID と対象の型の頭の ID から作る。
- **instance** は、元の宣言と引数の正規の表現（キー）で識別する。同じキーは、
  どこかが参照を持っている間は同じ参照を返す。生成物の参照も、その所有者を保持する。
  元の宣言は `origin` で引ける。宇宙のインスタンスは元の宣言の ID と宇宙引数をキーにし、
  その構成子と消去子はインスタンスの ID から決まる。
- **ソート**（`Prop`、`Type`、`Type<n>`）は参照の属性である。表示名が `Type7` であるだけの宣言は
  ソートではない。ソートの参照は処理全体で一つに決まる。
- **core が規則を持つ宣言**（`Nat`、`Zero`、`Succ`、`Bool`、`true`、`false`、算術、
  `Nat` の補助関数、`Quot` と `Eq`）の参照は、どの検査セッションでも同じである。その型と
  定義はほかの宣言と同じように core が受理する。

## 局所束縛の参照

`LocalRef` は束縛位置ごとに一つで、複製と表示名の付け替えは同じ ID を保つ。
行変数から作る操作と応答の束縛、再帰フィールドから作る帰納仮定（`LocalGeneration`）は、元の束縛の ID と生成の位置から決まり、
表示名の付け替えに影響されない。
捕獲を避けるために束縛を作り直すときは、別の局所 ID と元の束縛への参照を持つ。
穴の文脈をソースへ対応付ける処理は、この参照を使い、表示名の末尾から元の名前を推測しない。

相互再帰の精密化では、引数の位置と、それ以前の引数を対応付けた型の構造が同じ束縛を、
共有する消去の文脈の局所 ID に対応付ける。関数名や引数の表示名は対応付けに使わない。
生成した各関数の項で自由に現れる引数の参照は、その関数の元の局所 ID に戻してから
core に渡す。共有する消去の腕の中で束縛された参照は、その束縛の ID を保つ。

## 選択と effect

`Selection` は、型が決まるまで選べない宣言（型の頭で決まる構成子など）の候補を、
ID の順に整列し重複を除いて持つ。候補は空にできない。裸のパターンには、その位置が束縛になる場合の局所 ID も保持する。
同一性は候補の集合とこの局所 ID で決まり、表示名では決まらない。
選ぶ処理は、期待する型に合う候補がちょうど一つのときだけ参照を返す。
実行用の型と構成子が同じ綴りを持つ場合も候補を保持し、型の記述では型の宣言を、
値の記述では期待する型に合う構成子を選ぶ。
実行用の裸のパターンは、期待する型の構成子にフィールドがある場合、保持した局所 ID を束縛する。
その腕の使用箇所は同じ候補と局所 ID を保持し、検査で束縛として扱った箇所はその局所 ID に確定する。
候補にない宣言を後段で綴りから追加しない。

`EffectUse` は、束縛した effect の参照、引数の正規の表現、全称かどうか、行パラメータの
局所参照で同一性が決まる。引数の正規の表現は、束縛した参照を表示名でなく ID で区別して作る。

## `Declarations`

`Declarations` は、完全名から宣言への索引で、予約と可視を分ける。

- **予約**（`reserve`）は完全名に参照を与える。予約した参照は、その表の複製の間で共有する。
  その名前は `get` では見つからない。
- **可視**（`declare`）は名前を表に入れる。可視性は表ごとで、複製した表の一方で
  宣言しても他方では見えない。すでに可視な名前の宣言は、その参照を返して拒否する。
- `fork` は可視な名前を引き継ぎ、予約を共有しない表を作る。以後の予約は各々のものになる。
- 構成子と生成される宣言は、所有者から参照を作って可視にする。構成子は表に構成子として記録される。
- 別の表で同じ完全名を宣言すると、別の宣言になる。

意味上の環境（型や本体を持つもの）は `Declarations` ではなく `DeclRef` をキーにする。

## 表層の束縛

`SurfaceTerm` の識別子、宣言名、局所束縛、効果行は `Name` を持つ。
`resolve::Resolver` は修飾済みの構文を受け取り、宣言の索引と局所文脈で
`Spelled` を束縛する。すでに ID を持つ参照は、その表示名を調べず保持する。
同じ構文の複製を同じセッションで束縛すると、対応する局所束縛は同じ ID を持つ。

表層の `bindings::Bindings` は、宣言の予約、ソースから見える綴り、構成子の
候補を区別する。言語ライブラリの参照表は表層にあり、ID 型自身はライブラリを
読み込まない。ソースの修飾処理が書き換えるのは `Spelled` だけである。

マクロ展開とモデルの名前付けの後、ファイルごとに参照を束縛する。構成子の候補は、
そのファイルから見える型と構成子の ID に限定する。別のファイルに同名の構成子が
あっても、この候補集合を広げない。局所束縛による遮蔽もこの時点で区別する。
自ファイルの型は宣言から直接参照を得る。短い名前が曖昧でも、それぞれの宣言の
完全な名前は可視な名前の表に保持する。マクロ展開後の修飾でも、完全名を持つ宣言の
可視性を保持し、直接 import・公開範囲・import の一覧による制約を適用する。
束縛した構文木を検査と実行で共有し、すでに解決した参照は可視性の違いで差し替えない。

ライブラリの参照を引き継いだ表でソースの宣言を定義しても、同じ表示名のライブラリの
ID は使い回さない。ライブラリ自身の定義を束縛する入口だけが、ライブラリの ID を
使う。すでに ID を持つ宣言と、所有者から予約された生成宣言は、定義時にもその ID を保つ。
構文宣言が生成する解析関数と実行用のフィールド型は、組み込みの型・操作をライブラリの
ID で保持する。構文の型や構成子が同じ綴りを持っても、その参照を置き換えない。

モジュールの平坦化とモデルの名前付けは未解決の綴りだけを書き換える。型付きマクロへ
渡す項と型は、検査対象と同じ宣言・局所束縛の参照を持つ。型から構文値への変換は
構文木を組み立て、表示した型を読み直さない。精密化ホストが返す成功・失敗の値も、
標準ライブラリの構成子の参照を保持する。

実行用の型検査で組み込み型を選ぶのは、その宣言の ID との一致による。
NIR の型の依存集合と入れ子関数の索引も ID をキーにする。


## マクロの宣言参照

`SynIdent` は表示用の `name`、局所の衛生に使う `ctx`、位置の `span` と、
`declaration: Option(SynDeclaration)` を持つ。`SynDeclaration` は外部型であり、
マクロのソースにその値を作る構成子や数値からの変換はない。

`Syn::global` は、実行中のマクロの定義元で見える宣言を一度だけ解決し、
その参照を持つ識別子を返す。名前が見えない場合や一意でない場合はエラーになる。
マクロ評価と最終プログラムの束縛は同じ宣言表を使う。

構文値から項へ戻すとき、`declaration` があればその ID を使う。表示名やスコープからは
解決し直さない。`Syn::ident_like` と `Syn::decl_name` はスコープを借りて別の名前を
作る操作なので、元の宣言参照を引き継がない。局所変数の束縛位置に宣言参照を渡すと拒否する。
`Syn::same_ident` は両方が参照を持つ場合は ID を比較し、片方だけが持つ場合は異なるものとする。

実行用の構文にある宣言値にはソースのリテラルがない。NIR はこれをパッケージの宣言表の
スロットとして持つ。VM は表の参照を保持し、コード生成はスロットごとに一つの不透明な
値を作る。スロットの番号はパッケージ内だけで意味を持ち、表示名をキーにしない。

## core の定数

core の項の定数、宣言の型と本体、帰納型、構成子、消去子、簡約の記録は
`DeclRef` をキーにする。定数の等しさは参照の等しさであり、別の core の環境で
同じ名前として宣言された定数とは等しくならない。

名前つきの項の `Global` は、その宣言の参照のまま core に入る。局所文脈で
同じ表示名を探す処理は挟まない。core の束縛子の表示情報は元の局所参照も保持し、
穴の文脈を表層へ返す際にはその参照を引き継ぐ。この情報は項の等しさや型付け規則に影響しない。
精密化中の問い合わせでは、再帰関数の型をその宣言の
ID を持つ仮定として渡せる。この仮定は問い合わせの中だけで有効で、閉じた宣言の
環境へ登録されない。ソースの綴りを読む境界の索引に名前があるだけでは
受理済みとはならない。参照の型は、core が検査して登録した
宣言の環境からだけ得られる。帰納型の検査に失敗した場合は、宣言の環境、名前の
索引、構成子と消去子の対応を検査前へ戻す。

組み込みの簡約は、対象の primitive の参照との一致で選ぶ。表示名が `Zero` や
`Nat::eq` であるだけの参照には適用しない。再帰的な消去の行き先は宣言の参照を
保持し、型の表示名から消去子の名前を作って探し直さない。
入れ子の帰納型の引数も、位置情報を除いた項と参照の構造で照合する。

## 証明キャッシュの参照

キャッシュの鍵は束縛済みの構文と検査環境を含む。環境内の宣言に番号を割り当て、
保存された参照はその番号で表す。読み込みは番号からその環境の ID を受け取り、
ソース名として解決し直さない。局所束縛にも番号を付け、読み込んだ束縛と使用箇所に
同じ局所 ID を与える。ソースにある局所束縛のスロットは、読み込み先のソースの束縛へ対応付ける。未解決のソース名や表の範囲外の番号は、保存された項の参照として受け付けない。

表示名は表の順序を定めるためにだけ使う。同じ表示名の別の宣言があって順序を
一意に定められない環境は、永続キャッシュを使わず検査する。

## マクロの実行する関数と構成子

マクロの登録は定義元でソース名を解決し、関数の宣言 ID を保持する。
実行ライブラリから同じ ID の関数を取得し、その型と効果を検査する。
評価器へは選んだ関数の参照を渡す。呼び出し先の効果をたどる処理も宣言の参照で行う。

構文に登録するフォーマッタと色分け関数も、プログラムの束縛時に宣言の参照を保持する。
登録の検証とエディタでの実行は同じ参照を使い、表示名が一致する別の関数を選ばない。

`Elab::siblings` と `Elab::constructor_arity` は `SynIdent` を受け取る。
宣言参照があればその参照を調べ、参照のないソース識別子だけを呼び出し元の環境で解決する。
`Elab::siblings` が返す識別子は、各構成子の宣言参照を持つ。

マクロとホストが受け渡す構文値の構成子は `Name` を持つ。評価器が返す値は構成子の
参照を保持し、同じ表示名の別の構成子として読み直さない。ホストが作るスキーマの
入力はソース名を使えるが、構成子が一つに決まらなければ拒否する。参照として渡した
構成子が環境にない場合、表示名による検索には戻らない。

## 引用の大域参照

`quote` を構文値に変換するとき、定義元で一意に見える大域参照は、その宣言の ID を
`SynIdent` に持たせる。表示名やスコープを書き換えても、その参照先は変わらない。
引用の中で作る宣言と局所束縛は、この時点では構文として残り、展開ごとに束縛される。
引用内の束縛が定義元の大域名を隠す場合、その使用箇所を大域参照にしない。

## 検査から実行への参照

抽出の入力は、検査した宣言の情報と、その検査に使った展開済みの構文木を一緒に保持する。
抽出は構文木から証明引数・証明フィールド・型にしか使わないパラメータを取り除く。
残る宣言と局所束縛は同じ ID を使う。実行のためにソース文字列へ戻して読み直す処理はない。
マクロが呼び出す証明言語の関数も、この構文木の変換で実行用の宣言を得る。
標準ライブラリの組み込み表現への対応は、読み込んだファイルに属する宣言 ID で判定する。
帰納的な構文の宣言が作る実行用の型と関数は、生成時に記録した宣言参照を引き継ぐ。

構成子を型から選んだ結果は、式の頭または腕の構文の出現 ID に結び付けて保存する。
式とパターンの選択は区別し、抽出が受け取る式には検査が選んだ宣言参照を適用する。
キャッシュには宣言中の出現の番号を保存し、読み込み時に同じ位置の出現 ID に対応付ける。
ソースの位置は診断に使い、構成子の選択を引くキーには使わない。

組み込みの実行表現への変換は、検査した型・構成子の ID と対応する実行表現の ID の間で行う。
コンパイラの補助関数は独立した環境で束縛し、利用者の同名宣言で置き換わらない。
補助関数の固定した構文に、利用者の構文を ID を保った部分木として挿入する。

暗黙引数を補った適用は、式の出現 ID、呼び出し先 ID、書かれた引数の数と、補った項を保持する。
同じ出現の記録を照合するときも、項の表示ではなく参照を含む構造を比較する。
局所的な可変状態の実行時の型は、束縛の局所 ID に対応付ける。初期値のソース位置では識別しない。
適用項の走査は出現 ID を保つ。精密化で別の項を作る場合は元の出現との対応を記録し、
補った引数を元の出現に結び付ける。
依存型の抽出が生成する補助構文は、利用者の宣言・局所参照を内部のスロットとして受け渡す。
スロットから構文木へ戻すときは保存した参照を使い、表示名で解決し直さない。
生成した補助宣言は、利用者の宣言から独立した環境で束縛する。

終了性の検査結果は宣言 ID の集合として引き継ぐ。この結果を使えるのは、抽出したプログラムと
実行用に検査するプログラムが一致している場合に限る。宣言 ID を持つこと自体は、型や終了性を
検査済みであることを意味しない。

## 抽出したソースの書き出し

ソースを書き出すときは、抽出した構文木の複製に出力用の名前を割り当てる。
宣言と局所束縛の参照をキーとし、同じ表示名の別の参照には異なる名前を割り当てる。
モジュール名と言語ライブラリの名前も予約し、出力した局所束縛がそれらを隠さないようにする。
構成子の候補は、同じ構文木を検査した型から宣言の参照に確定してから書き出す。
型の記述で選んだ宣言は、型検査が記録した出現 ID と宣言 ID の対応を使う。
effect の腕のパターンは検査済みの操作の引数型を、戻り値の腕は処理本体の型を使う。

出力先に定義されず言語ライブラリにもない宣言、選べなかった構成子、不透明な宣言値は
書き出しを拒否する。宣言値に表示名や数値を代入する処理はない。
書き出したソースには検査済みの終了性を表す証拠を付けず、読み直したプログラムは独立に検査する。

## 証明の編集用の書き出し

編集用の項は、挿入先で見えるソース名と宣言 ID の対応、局所束縛の ID を使って書き出す。
補完候補は参照を保持し、候補を絞るソース名を解決した参照と直接比較する。
内部の束縛には、挿入先の局所名と宣言名を隠さない名前を割り当てる。
書き出した項を同じ環境で読み直し、大域参照が同じ ID を指し、局所束縛と使用箇所の
対応が保存されることを確かめる。名前を割り当てられない参照や、往復で参照が変わる項は
書き出しを拒否する。診断だけの表示には、この往復の保証を要求しない。

## JavaScript のホスト表現

データの所有者を表す実行時の記号は、パッケージの宣言 ID から割り当てる。
表示名が一意で、言語ライブラリの予約した名前でもなければ、その表示名を使う。
同じ表示名の宣言が複数ある場合は、宣言表の位置を使って別々の記号を割り当てる。
言語ライブラリの組み込み表現には、その宣言 ID に対応する予約済みの記号を使う。
構成子は所有者の記号と構成子のタグの組で区別し、タグだけから宣言を選ばない。
