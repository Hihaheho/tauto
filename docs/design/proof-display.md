# 証明の表示

`tauto proof FILE [NAME] [--format block|node|tree|tree-html|natural|json] [--full] [--output FILE]` は、
対象ファイルの本文を持つ定理の導出を表示する。名前を指定するとその定理だけを表示する。
import 先の定理は表示対象に含めない。名前が重複すると拒否する。

人が読む表示では、正常に検査でき、公理に依存しない定理には判定を添えず、定理名だけを表示する。
未完成・検査失敗・未検査と公理への依存は明示する。JSON は常に `status` を持つ。

## 導出

カーネルの最終的な証明の検査で、各判断の文脈、項、型、推論規則、前提の判断を記録する。
導出の記録は証明キャッシュを使わない。表示器は型付けや変換の規則を持たない。
表示する定理の引数は最初の文脈の仮定とし、関数の導入の下で使える局所的な仮定も文脈で区別する。
導入では閉じる仮定を明示する。

関数の適用は、関数の型と引数の型の判断を前提に、適用した項の型を結論とする。
変換や宇宙の包含によって型を合わせた判断は、その変換前の判断を前提として持つ。
場合分けと局所定義は精密化された項の導出として表示する。
帰納型の除去は実際の eliminator とその各引数の型付きの判断として表示する。

穴とカーネルに証明のない参照は未証明の前提であり、検査済みの葉として扱わない。
それに依存する結論も未完成として表示する。検査に失敗して導出を得られない場合は、
失敗の診断と導出がないことを表示し、構文から推論を補わない。
公理への依存、import 先や対象外の定理の失敗・未完成は検査結果に残る。

## 形式

- `block`: 推論を入れ子のブロック、前提の判断を型付きのスロット、結論を出力として持つ HTML。
  ブロックは開閉でき、局所的な仮定を閉じる場所を表示する。
- `node`: 推論をノード、前提の判断を入力端子、結論を出力端子として持つ HTML。
  線は、その前提を導くノードの出力と、前提を要求する入力を結ぶ。端子に文脈と型を表示する。
- `tree`: 前提を上、結論を下に置き、Unicode の推論線に規則を付ける証明木。
  文脈は `Γ` と番号で参照し、一覧に各仮定を表示する。項と型の文字は Unicode のまま保つ。
- `tree-html`: 同じ導出木を HTML で表示する。前提を横に並べ、その下に推論線と規則、結論を置く。
- `natural`: 数学の文章として、後続から参照する推論のまとまりに番号を付ける Unicode の証明。既定の形式。
  仮定、使用した補題、計算、結論を示す。文言は CLI の言語設定に従う。
- `json`: 記録された完全な導出を、構造を持つ JSON として出力する。自然言語表示の規則は適用しない。

HTML は閲覧専用で、スタイルを含む単一ファイルである。外部リソースや JavaScript を読み込まない。
ソースに由来する文字列は HTML としてエスケープする。同じ型の端子と線は同じ色になる。
未証明の前提を含むブロックとノードは破線で表示する。

`--output` がなければ標準出力へ書く。指定した出力ファイルは新規作成し、既存ファイルは上書きしない。
終了コードは成功が 0、検査または入出力の失敗が 1、引数の誤りが 2、未完成が 3。
選択した定理以外や import 先の検査失敗・未完成も終了コードに反映する。

## 自然言語表示の規則

仮定と目標を先に示し、検査済みの導出を、仮定・結論・証拠・依存関係を保つ説明へまとめる。
表示器は証明を探索せず、各説明の根拠を記録された判断から取る。
完全な判断・前提・規則は他の表示形式で参照でき、表示のまとめは定理の検査結果を変えない。

完全な型注釈の適用は、注釈の型付けに証明の手順が含まれず、本体と結論の型の定義的同値を
確認できる場合に本体の説明へまとめる。命題の形成と宇宙の包含を独立した証明の手順として再掲しない。
証明の型を合わせる定義的な変換は隣接する推論へ吸収し、その結論を表示する。
反射性から計算で目標を閉じる変換は、始点と終点の説明を残す。
等式に沿う依存型の移送は定義的な型合わせとして省略しない。

等式の合同性・対称性・推移性は、宣言の参照と適用した引数、前提・結論の端点の対応を
確認し、理由付きの等式列として表示する。端点の照合は構造の一致かカーネルの定義的同値による。
合同性で変える位置は両辺の式に示し、逆向きの使用は理由に示す。
他からも使う中間結果は参照として残す。結合律などの定理による変形の理由は省略しない。

帰納型の生成された除去則は、単独の帰納型のパラメータ・モチーフ・各構成子の分岐・添字・対象が
対応し、分岐の仮定の数を確認できる場合に、分解・場合分け・帰納法として表示する。
再帰位置のある型では帰納仮説を使わなくても帰納法とする。分岐の仮定と依存する目標は分岐内に残す。
分岐の項・目標・必要な仮定の型から参照されない局所変数は省く。分岐末尾で関数型を一引数ずつ再掲しない。相互帰納型など対応を確認できない除去則は通常の適用で表示する。

命題の構成子の適用は、選んだ構成子とデータ、証明引数の条件と証拠を示す。
引数は依存する順序で扱い、結論の添字を保持する。反射性は両辺の対応を確認して説明する。

仮定や宣言の参照と値は使用箇所に書く。宣言の暗黙引数のうち、証明や内部の証明手順を含まないものは
適用の引数列から省く。一度だけ使う短い証明の適用は使用箇所にまとめる。
後続から参照する結果に出現順の番号を付ける。同じ文脈・項・型の結果は番号を共有する。
宣言と自由な局所参照は ID で比較し、項の中で束縛された変数の改名は区別しない。
仮定を導入した範囲ごとに共有の範囲を分け、別の分岐で得た結果を流用しない。
生成された局所名の表示は束縛の ID を保って整え、他の局所名と衝突しない名前を使う。

未証明のゴール・参照と、それらに依存する判断は縮約せず、未完成の説明として残す。
表示のための問い合わせは検査済みの環境のコピーで行い、一回 4096 ステップに制限する。
対応を確認できない場合は元の型付きの判断や記録された型変換を表示する。

## 完全な表示

`--full` は定理の引数を導入する部分も含む、記録された証明の導出を表示する。
`natural` では判断を共有せず、部分適用、仮定・宣言の参照、値や型の確認も各判断として番号を付ける。
推論の組み立てとすべての型付きの判断を残し、自然言語表示のまとめや省略の規則を適用しない。
未証明の判断と、それに依存する判断も未完成と表示する。
他の表示形式では定理の引数の導入まで含む導出を表示する。
これは最終的な証明の検査の導出であり、読み込みや精密化などの全処理の履歴ではない。

## JSON

トップレベルの `version` は形式の版で、値は 1。
`status` はファイル全体の判定で、`ok`、`incomplete`、`failed` のいずれか。
`proofs` は選択した定理の順序付きの一覧。各要素は次の項目を持つ。

| 項目 | 内容 |
|---|---|
| `name`, `status` | 定理名と判定。判定は `checked`、`incomplete`、`failed`、`skipped` |
| `parameters`, `implicit` | 宣言に書かれた引数の一覧と、先頭の暗黙引数の数 |
| `goal`, `goal_tree` | 宣言の結論の文字列と項の構造 |
| `axioms`, `uses` | 依存する公理と、未完成な宣言の名前の一覧 |
| `holes` | 穴の名前 `name`、ゴール `goal`・`goal_tree`、文脈 `context` の一覧 |
| `error` | 失敗・検査対象外の理由。該当しなければ `null` |
| `derivation` | 完全な導出の根。記録がなければ `null` |

導出の各節点は、定理内で前置順に振った `id`、推論規則の識別子 `rule`、未証明の葉を含まないかを表す `complete`、
文脈 `context`、項 `term`・`term_tree`、型 `type`・`type_tree`、導入した仮定 `introduced`、前提 `premises` を持つ。
`rule` は `assumption`、`constant`、`unverified`、`literal`、`sort`、`formation`、
`introduction`、`application`、`conversion`、`reduction`、`hole` のいずれか。
引数・文脈・導入した仮定の各要素は `name`、`type`、`type_tree` を持つ。
項の構造は `tauto elaborate --json` と同じ項の表現を使う。
`complete` は開いた葉の有無を表す情報であり、定理が受理されたかは `status` で判断する。

JSON は `--full` の有無によらず、定理の引数の導入を含む完全な導出を出力する。
項目名と判定・規則の識別子は言語設定に依存しない。診断の文章は言語設定に従う。
読み込みに失敗して出力を構成できない場合は標準エラー出力へ診断を書き、終了コード 1 で終わる。

## マクロの表記

人が読む表示では、式を返すマクロの展開結果に対応する元の呼び出しを表記として使う。
マクロ名を含む、ソースに書かれた呼び出し全体を保存する。DSL の意味を推測した説明や、
計算結果からの逆変換は行わない。説明の根拠とステップのまとめ方は展開後の導出から決める。
JSON は展開後の項と構造を保持する。

対応表は定理ごとに作り、ソースと精密化後の項に残る展開の出現情報を使う。
位置を除いた項の構造、型引数、宣言・局所参照と引数の文脈を照合する。
項の中で束縛された変数の改名は区別しない。計算して等しくなるだけの項は一致としない。
同じ構造と文脈では候補の表記が一意なときだけ使う。表示用の改名で束縛名が変わる場合は使わない。
出現の ID だけでは表記を選ばず、印字する項の構造も照合する。
大域参照のソース上の別名は記録しないため、大域参照を含む表記は元と同じ長さの文脈でだけ使う。
局所参照だけの項では、元の束縛を同じ綴りの別の束縛が隠さない場合に文脈の拡張を許す。
部分式にも同じ規則を適用し、HTML では呼び出しの文字列もエスケープする。

対応を収集する文脈は定理の引数までとする。内側の束縛を越えた収集、展開が作った
別のマクロ呼び出し、文を返すマクロの表記の復元は行わない。
文脈が一致しない、束縛名が重なる、候補が複数ある、精密化で展開の出現を失う場合は、通常の項の表記を使う。

## エディタの hover

`tauto lsp` は、定理の宣言の `theorem` キーワードと定理名、および定理名の参照で、
シグネチャの下に `natural` 形式の証明を表示する。証明の改行と字下げを保ち、
ソースに由来する文字列を Markdown として解釈しない。言語は LSP 起動時の CLI の言語設定に従う。

表示は開いているファイルと import 先の未保存の編集を含むスナップショットから作る。
定理ごとに必要時に導出を記録して表示をキャッシュし、開いているファイルの変更・開閉時に破棄する。
未完成・検査失敗・公理依存の状態はコマンドと同じ表示に含む。
読み込みや表示に失敗した場合はシグネチャを表示する。
