# elaborator

Tauto の表層構文から、独立カーネルが検査する名前なしの項を構築する精密化器。
`surface` の構文木を入力にし、`kernel` の型推論・変換・最終宣言検査を使う。
Rust の精密化 API を呼ばず、既に精密化された項を入力する再生器でもない。
`nibcheck`（実行言語の型検査）とは別の、証明言語の部分言語を扱う。

## 対応範囲

* 本体と型を明示した `def` と `theorem`、先に検査した宣言の参照。
* 名前付きの局所変数、従属する関数型、期待型で検査するラムダ、関数適用。
* `the(T, value)` による型注釈、純粋な不変 `let` と末尾の値からなるブロック。
* `Prop`、`Type`、数値レベル `Type0`〜`Type1000`。`true`・`false` は `Bool::true`・`Bool::false` の参照になり、`Bool` を宣言した環境でだけ受理される。
* 宣言の暗黙引数（`<A: Type>`、`fn` のジェネリクス）と、構成子の族パラメータ。呼び出しでは暗黙引数を穴にして、期待する結果型と各明示引数の型を一階で照合して解く。解けない穴が残ればエラーにする。解いた値を引数にした適用を kernel が検査する。再帰呼び出しでは暗黙引数を省き、宣言自身のものをそのまま使う。
* 型を明示した全域な `fn`（借用・効果・制約なし）。Rust と同じく、本体つきの不透明な宣言として検査し、続けてその値を与える。
* 添字のない一つの族の変数への `match`（構成子ごとに一つの腕、各フィールドは変数か `_`）。族の eliminator に、パラメータ、期待型（または `match x: T` の `T`）から作る motive、構成子ごとの場合、変数を渡す。宣言のパラメータへの match では、再帰呼び出しのうち、再帰的なフィールドを渡し他のパラメータをそのまま渡すものを帰納法の仮定に置き換える。それ以外の再帰呼び出しは拒否する。
* ネストした構成子パターン（`S(S(m))`、`Mk(Z, b)`）、数値と `true`/`false` のパターン、最後の `_ =>`。ホストと同じく、全ての腕が分解する列だけを分解する平らな match の木に書き換えてから上の match として elaborate する。腕の順序に依存する重なり、使われない `_ =>`、ガードは拒否する。
* 添字付きの族への `match`。添字が互いに異なる変数なら motive で添字と値を抽象する。再帰呼び出しはフィールドの添字を渡すものを帰納法の仮定に置き換える。変数でない添字は、ホストと同じく motive で等式 `i = a` として一般化し、eliminator に `Refl(a)` を渡す。各場合で等式を解き、異なる構成子なら添字の族の no-confusion で不可能な場合とし（腕は不要）、同じ構成子なら単射なフィールドの等式に分け、変数を等しい項で置き換えて腕を精密化してから `Eq::rec`（`Prop` へは `Eq::ind`）で戻す。この形での再帰呼び出し、マッチする値に言及する期待型、構成子と構成子でない項の等式、マッチする値や添字に型が依存する他の変数は拒否する。
* `mutual` ブロックの inductive 宣言を一つの kernel コマンドとして検査する。その族への match では、ホストと同じく他の族の motive を `Unit`、場合を `Unit::Star` にする（`Unit` は kernel にだけ宣言し、出力しない）。関数の `mutual` と、族をまたぐ相互再帰は拒否する。
* 関数の `mutual` で、全ての関数が添字のない同じ族の同じパラメータに match するもの。ホストの aligned group と同じく、一つの eliminator で値の組（入れ子の `BelowPair`）を計算し、各関数をその成分として宣言する。`BelowPair` は `Unit` と同様に kernel にだけ宣言する。
* フィールドより深い部分への再帰（`S(S(m)) => f(m)` や、腕の中のフィールドへの match の中の呼び出し）。ホストと同じく、motive で各値をその部分の値の組（`below`、族の eliminator で `Type` へ計算する）と組にし、部分への match はその `below` を一般化する。関数型の再帰フィールドを持つ族と、作り直した構成子への呼び出しは拒否する。
* 宇宙多相（ホストと同じく実体化による）。先頭の暗黙引数が `Level` 型の `def`・`theorem` はテンプレートで、宣言時に水準を変数のまま一度検査し（出力しない）、水準を数値で書いた呼び出し `f(1, …)` を実体 `f@1` の呼び出しとして読む。実体は最初に呼ばれた宣言の直前に通常の宣言として検査・出力する（`def` はホストと同じく不透明に宣言してから値を与える）。`Type(u)`、`u + n`、`max(a, b)` を水準として扱う。テンプレートの中からは自身の水準で他のテンプレートを呼べ、その実体はホストと同じ順に先に宣言する。水準パラメータを持つ `inductive`（`UBox(u: Level, A: Type(u))`）もテンプレートで、`UBox(1, …)` や構成子 `UBox::Ubox(0, a)` は実体 `UBox@0`・`UBox@0::Ubox` を読み、実体には通常の族と同じく no-confusion を作る（kernel が受理しない `noconf` はホストと同じく省く）。水準が数値でも水準変数でもない呼び出しと、実体の族への `match` は拒否する。
* 一つの帰納型族の `inductive` 宣言（パラメータ、添字つきの型、明示的な引数の構成子）。族の名前をその型で仮定して構成子の型を精密化し、仮定を捨ててから kernel の `KernelInductive` で検査する。正値性・宇宙・構成子の結果の形の判定は kernel だけが行う。続けて、ホストと同じく添字のない族ごとに no-confusion の定義（`::nc`・`::nc_diag`・`::noconf`）を族の eliminator から作り、kernel で検査して出力する。

束縛変数には新しい自由原子を割り当て、バインダを閉じるときに de Bruijn 添字へ
抽象化する。型中の依存関係も同じスコープを使う。宣言の型が型であること、本体の型、
閉じた項であることを検査し、最後に `kernel_execute` で宣言を再検査する。
穴、推論できないラムダ、誤った型、未知の名前を受理へ変えない。
失敗と燃料切れでは宣言登録前の環境を復元する。

高階の単一化・構成子の暗黙引数・タクティクス・
マクロ・効果・import・クラス・生成宣言・属性は未対応。未対応の宣言や構文を拒否する。
prelude 全体はロードせず、`Nat` などを暗黙に公理として追加しない。生成する項が使う `Unit`・`BelowPair`・`Eq` だけを kernel に宣言し、出力はしない。
数値リテラルの読み取りは 2^63−1 以下の十進数に限られ、`Nat` の宣言がない環境で
自然数を使う宣言を受理しない。診断は現状、入力ファイル名と失敗の種類まで。

## 実行

```sh
cargo run --locked -p tauto-cli -- build --release totes/elaborator
target/tauto/target/release/elaborator example.taut
cargo test --locked --manifest-path tools/selfhost-harness/Cargo.toml --test elaborator
```

入力例:

```tauto
theorem identity(A: Prop, a: A): A { a }
```

出力:

```text
D identity p s P p b 0 b 1 1 l l b 0 0
```

出力形式は `totes/kernel` の宣言再生形式。一つのファイルの全宣言が成功してから
出力し、失敗したファイルについて途中までの宣言は出力しない。
各入力ファイルは独立した環境で精密化する。`def` は透明、`theorem` は不透明。
入出力の殻以外の関数は Tauto の証明言語で書き、型と全域性を二つの Rust カーネルで
検査してから既存の抽出・Rust backend で実行する。

差分試験は同じ証明ソースについて、Rust 側の独立カーネルへの翻訳と
生成した名前なしの項を比較する。型検査の拒否、依存関係、外側の変数の捕捉、
高階の適用、数値宇宙、日本語の名前、評価器での実行も対象にする。
型注釈は Rust 側が `the` の適用として残す一方、この精密化器は検査後に消去するため、
注釈と let の試験は Rust 側での受理と出力のスナップショットを比較する。
名前の隠蔽、透明性、ファイル単位の出力、拒否・燃料切れ後の環境復元も回帰試験に含む。

通常の `tauto check` の精密化器を置換してはいない。Tauto で書かれた精密化処理を
実際のソース入力から実行する独立したコンパイラ段階であり、完全なコンパイラの
セルフホストや stage1→stage2 の成立を示すものではない。実装全体の健全性定理もない。
