# elaborator

Tauto の表層構文から、独立カーネルが検査する名前なしの項を構築する精密化器。
`surface` の構文木を入力にし、`kernel` の型推論・変換・最終宣言検査を使う。
Rust の精密化 API を呼ばず、既に精密化された項を入力する再生器でもない。
`nibcheck`（実行言語の型検査）とは別の、証明言語の部分言語を扱う。

## 対応範囲

* 本体と型を明示した `def` と `theorem`、先に検査した宣言の参照。
* 名前付きの局所変数、従属する関数型、期待型で検査するラムダ、関数適用。
* `the(T, value)` による型注釈、純粋な不変 `let` と末尾の値からなるブロック。
* `Prop`、`Type`、数値レベル `Type0`〜`Type1000`、`Bool`。

束縛変数には新しい自由原子を割り当て、バインダを閉じるときに de Bruijn 添字へ
抽象化する。型中の依存関係も同じスコープを使う。宣言の型が型であること、本体の型、
閉じた項であることを検査し、最後に `kernel_execute` で宣言を再検査する。
穴、推論できないラムダ、誤った型、未知の名前を受理へ変えない。
失敗と燃料切れでは宣言登録前の環境を復元する。

暗黙引数・メタ変数・宇宙変数・帰納型・再帰・パターンマッチ・タクティクス・
マクロ・効果・import・クラス・生成宣言・属性は未対応。未対応の宣言や構文を拒否する。
prelude 全体はロードせず、`Nat` や `Eq` などを暗黙に公理として追加しない。
数値リテラルの読み取りは 2^63−1 以下の十進数に限られ、`Nat` の宣言がない環境で
自然数を使う宣言を受理しない。診断は現状、入力ファイル名と失敗の種類まで。

## 実行

```sh
cargo run --locked -p tauto-cli -- build --release totes/elaborator
target/tauto/target/release/elaborator example.taut
cargo test --locked -p tauto-selfhost --test elaborator
```

入力例:

```tauto
theorem identity(A: Prop, a: A): A { a }
```

出力:

```text
D identity p s P p b 0 b 1 1 l l b 0 0
```

出力形式は `totes/kernel` の宣言再生形式。一つのファイルの全宣言が成功してから
出力し、失敗したファイルについて途中までの宣言は出力しない。
各入力ファイルは独立した環境で精密化する。`def` は透明、`theorem` は不透明。
入出力の殻以外の関数は Tauto の証明言語で書き、型と全域性を二つの Rust カーネルで
検査してから既存の抽出・Rust backend で実行する。

差分試験は同じ証明ソースについて、Rust 側の独立カーネルへの翻訳と
生成した名前なしの項を比較する。型検査の拒否、依存関係、外側の変数の捕捉、
高階の適用、数値宇宙、日本語の名前、評価器での実行も対象にする。
型注釈は Rust 側が `the` の適用として残す一方、この精密化器は検査後に消去するため、
注釈と let の試験は Rust 側での受理と出力のスナップショットを比較する。
名前の隠蔽、透明性、ファイル単位の出力、拒否・燃料切れ後の環境復元も回帰試験に含む。

通常の `tauto check` の精密化器を置換してはいない。Tauto で書かれた精密化処理を
実際のソース入力から実行する独立したコンパイラ段階であり、完全なコンパイラの
セルフホストや stage1→stage2 の成立を示すものではない。実装全体の健全性定理もない。
