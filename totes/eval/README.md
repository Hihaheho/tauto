# eval

実用 VM の入力である `Cps` を直接評価する、証明言語のライブラリ。
`e_eval` はコンパイラ、VM の `step`、`mrun` を呼ばず、式と引数を左から右に評価する。
局所名はソースの識別子で引き、VM のスロット番号とは区別する。

## 実装

`src/value.taut` は値、局所環境、共有セルからの読み出しと参照の読み出し、
基本演算の選択を持つ。入力型は `totes/vm/src/cps.taut`、値とヒープの表現は
`totes/vm/src/mval.taut`、基本演算は `totes/vm/src/operations.taut` を共有する。
基本演算の算術そのものを別の実装で検証する構成ではない。

`src/eval.taut` はリテラル、局所変数、基本演算、単項操作、分岐、式の列を扱う。
成功は値とヒープを返す。実行時エラー、検査用の燃料切れ、未対応の構文は別の結果で、
成功として扱わない。燃料は評価の深さを制限し、プログラム中の `budget` の歩数ではない。
引数の個数が基本演算の個数と違うときは拒否する。

関数呼出し、末尾呼出し、組込み関数、定義、代入、ループ、return、パターン照合、
クロージャ、効果、ハンドラ、借用、budget は `ErUnsupported` を返す。
タスクやホストとの対話を含む全プログラムの実行器ではない。

## 証明

`proof/eval.taut` が証明の入口である。

| ファイル | 命題の範囲 |
|---|---|
| `proof/value.taut` | 値と演算の選択がコンパイラと一致する。リテラルのコンパイルと実行、局所変数のスロット割当てが与えられたときのコード、通常・共有セル・参照の読み出しが値と残りの機械状態を保つ |
| `proof/operations.taut` | スタックから引数を元の順序で取り出す。個数の一致と演算結果が与えられたとき、直接評価と VM の演算命令が同じ成功結果またはエラーを返す |
| `proof/fuel.taut` | 燃料を増やしても完了した結果は変わらない。異なる燃料で成功した二つの評価は、値とヒープが等しい |
| `proof/results.taut` | 連続した評価の成功から各段の成功を取り出す。基本演算の成功から VM と共有する演算の結果を取り出す |
| `proof/steps.taut` | 有限の命令列を合成する。遷移の列と実用 VM の `mrun` は双方向に対応し、実行を区切って再開しても結果は同じ |
| `proof/unary.taut` | リテラルに任意の有限個の単項操作を重ねた実際の `Cps` 式について、直接評価が成功すれば、`c_expr` の生成したコードは同じ値とヒープを返す |
| `proof/arguments.taut` | 直接評価の成功から演算の引数個数の一致を導く。引数列と式の列のコードを、ヒープの更新順序とスタックを保って合成する |
| `proof/expressions.taut` | リテラル・単項操作・複数引数の基本演算・式の列を任意に入れ子にした式の、コンパイラの状態保存と実行結果の一致 |

`EUnaryExpr(n, e)` は、式 `e` がリテラルと単項操作からなり、命令数が `n` であることを表す。
`e_unary_expr_mrun` は、直接評価の成功を仮定に取り、実用 VM をちょうど `n` 命令進めた
結果の等式を結論に持つ。検査用の燃料と命令数は別である。
残りのコード、スロット、スタック、フレーム、初期ヒープは任意で、
単項操作によるセルの確保や参照の読み出しもこの定理に含む。
`e_unary_compile_state` は、コンパイルの燃料が命令数以上なら、
スロット・関数・診断を含むコンパイラの状態が保存されることを示す。
この単項操作の定理は、局所変数を含む式、複数引数の演算、分岐、式の列、エラー終了を含まない。

`EPrimitiveExpr` はリテラル・単項操作・基本演算・式の列からなる形を表し、
`EPrimitiveArgs` は各要素がその形である式列を表す。
`e_primitive_expr_correct`、`e_primitive_args_correct`、`e_primitive_sequence_correct` は
評価の燃料について相互帰納法で証明する。
直接評価が成功すると、同じ燃料でのコンパイルはスロット・関数・診断の状態を保ち、
生成されたコードは同じ値とヒープを返す。後続コード、スロット、元のスタック、フレームは任意である。
引数の評価は左から右にヒープを受け渡し、式の列では最後の値だけをスタックに残す。
`e_primitive_expr_mrun` は実用 VM の実行結果を等式として述べる。
命令数は `e_expression_steps`、`e_arguments_steps`、`e_sequence_steps` で数え、
値を捨てる命令も含む。演算の引数個数や演算結果を別の仮定として渡す必要はない。
この証明は成功した評価を対象とし、局所変数の読み出し、分岐、エラー終了を含まない。

局所変数の定理は、スロットとソース環境の値の対応を仮定する。
この対応をコンパイラ全体が構築・保存することは、その定理の結論には含まない。
引数列全体のコンパイル正当性は、`EPrimitiveArgs` を満たす式列について
`e_primitive_args_correct` が示す。

直接評価の一般定理には、共有する値の表示から `Text::of_float` への依存がある。
VM の実行関数を使う定理には、VM にある浮動小数点関数の公理への依存が届くものがある。
公理を宣言して不足する証明を補わず、各定理の依存集合をケースで検査する。

## 検査

`cases/check/direct-eval.eure` は宣言の受理と公理の依存集合を検査する。
参照の確保と読み出しを重ねた式について、一般定理からコンパイル後の実行結果を導く。
複数の引数での参照の確保、基本演算の入れ子、値を捨てる式の列、
空の式列と引数のない演算についても、直接評価とコンパイル後の結果を照合する。
`cases/eval/direct-cps.eure` は、演算、分岐、局所変数、ヒープ操作の順序、
エラーの伝播、燃料切れを計算で確かめる定理を持つ。

証明は `cargo test --locked -p tauto-test-suite --test cases -- check/direct-eval`、
評価結果は `cargo test --locked -p tauto-test-suite --test cases -- eval/direct-cps` で検査する。

## 未証明の範囲

全構文の直接評価、コンパイラによる環境とヒープの対応の保存、クロージャ変換、
継続の捕獲と再開、予算、タスク、ホスト要求、全プログラムの双方向の観測的等価性は
証明の対象であり、上の定理だけでは保証されない。
ソースから `CProgram` への変換と、Rust 評価器との対応も含まない。
予算の消費単位、ホストの応答、タスクのスケジュールをどう対応させるかは未決定である。
